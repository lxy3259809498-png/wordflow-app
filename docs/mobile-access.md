# 手机访问指南

## 一句话结论

**能。** 手机连同一个 Wi-Fi，浏览器输入：

```
http://192.168.35.167:5173
```

（`5173` 是开发服务器；若用 `npm run preview`，换成 `4173`。）

## 为什么不能用 localhost

`localhost` / `127.0.0.1` 在手机上指向**手机自己**，不是这台电脑。必须用电脑的局域网 IP。

本机实测地址：**192.168.35.167**（WLAN 网卡）。

换 Wi-Fi 或路由器重启后 IP 可能变化，重新查一次：

```powershell
Get-NetIPAddress -AddressFamily IPv4 |
  Where-Object { $_.IPAddress -notlike '127.*' -and $_.IPAddress -notlike '169.254.*' } |
  Select-Object IPAddress, InterfaceAlias
```

> 看到 `198.18.0.0`（mihomo）和 `172.24.0.1`（虚拟网卡）要忽略——那不是手机能连的地址。

## 前提条件（缺一不可）

1. **同一 Wi-Fi**：手机和电脑连同一个路由器。手机用 4G/5G 流量访问不了。
2. **服务监听所有网卡**：`vite.config.ts` 已设 `host: true`，`preview` 脚本已设 `--host 0.0.0.0`。已实测监听 `0.0.0.0:5173`。
3. **Windows 防火墙放行**：本机已存在 Node.js 入站允许规则，无需额外操作。
   - 若仍连不上：首次启动时 Windows 可能弹窗询问，选「允许访问」。或临时关闭专用网络防火墙测试。

## 手机上的功能差异

| 功能 | 局域网 HTTP | 说明 |
| --- | --- | --- |
| 背单词、复习、错词本 | ✅ 正常 | |
| 数据保存 | ✅ 正常 | 存在手机自己的 IndexedDB，与电脑**不互通** |
| 发音 | ✅ 正常 | 联网词典音频 / 系统语音 / 内置合成三级回退 |
| 词书导入导出 | ✅ 正常 | |
| **添加到主屏幕（PWA）** | ❌ **不可用** | 浏览器要求 HTTPS 才允许 Service Worker |
| **离线打开** | ❌ 不可用 | 同上 |

### 想要 PWA 与离线

两个办法：

1. **手机 Chrome 的 `chrome://flags`** 里开启 *Insecure origins treated as secure*，加入 `http://192.168.35.167:4173`。仅调试用，不推荐日常。
2. **用 HTTPS 部署**：`npm run build` 后把 `dist/` 放到任意 HTTPS 静态托管（Vercel / Netlify / Cloudflare Pages / 自己的 Nginx + 证书）。这样手机打开就是完整 PWA，可安装、可离线。

## 一个重要提醒：手机和电脑的数据是分开的

IndexedDB 存在**各自的浏览器里**，不共享。手机上学的进度不会同步到电脑。

想在两端之间搬运进度：

1. 电脑上「设置 → 数据与备份 → 导出 JSON 备份」
2. 把文件传到手机（微信/邮件/网盘）
3. 手机打开同一页面 → 「选择备份文件」→ 预览校验 → 覆盖恢复

## 常见问题

**打开是空白页 / 一直转圈**
检查是不是输入了 `localhost`。必须是 `192.168.x.x`。

**连接被拒绝**
- 电脑上的服务还在运行吗？（关掉终端就停了）
- 手机和电脑真的在同一个 Wi-Fi？有些路由器开了「AP 隔离」，设备之间互访被禁，需要关掉。
- 用的是访客网络？访客网络通常隔离设备。

**页面能开但很慢**
首次打开要把 1.4 万词写入手机 IndexedDB，中端手机约 5~15 秒。之后正常。这是真实的一次性成本，不是卡死。

**显示 "Blocked request"**
Vite 的主机名校验。`vite.config.ts` 里已设 `allowedHosts: true`，若仍出现，确认改的是这个配置文件并重启了服务。
